# React to a new booking

When a customer books, Sesami can notify your server with a webhook. The webhook tells you which booking changed. You then fetch the booking to get its customer, service, time and location.

In the API, bookings are called **appointments**, so queries, paths and topics use that name.

## 1. Receive the webhook

Subscribe to a booking topic such as `appointment.created`. Each delivery carries the booking id in `data.id`:

```json
{
  "topic": "appointment.created",
  "shop_id": "YOUR_SESAMI_ADMIN_SHOP_ID",
  "created_at": "2026-10-22T06:10:22.345Z",
  "hash": "9f2c4e6a8b0d1f3e5a7c9b2d4f6e8a0c1b3d5e7f",
  "data": { "id": "64f1c2a9e4b0a7d3c8e91b25", "type": "appointment" }
}
```

The other booking topics are `appointment.updated`, `appointment.cancelled`, `appointment.rescheduled`, `appointment.checkin` and `appointment.noshow`. They all have the same shape, so the next step works for each one.

## 2. Fetch the booking

Send the usual [request headers](./3-make-a-request.md). The `Shop:Read` permission is enough.

Pass `timezone` to choose the time zone for `datetime`, `rangeStart` and `rangeEnd`. It takes an IANA name such as `UTC` or `America/New_York`. Use `UTC` and convert on your side to avoid ambiguity.

<Tabs groupId="api" queryString>
<TabItem value="graphql" label="GraphQL" default>

One query returns the booking with its customer, service and resources:

```graphql
query GetBooking($id: String!, $timezone: String) {
  getAppointment(id: $id, timezone: $timezone) {
    id
    status
    datetime
    rangeStart
    rangeEnd
    customerTimezone
    variantTitle
    quantity
    price
    currency
    orderId
    orderName
    locationId
    customer {
      id
      firstName
      lastName
      email
      phone
    }
    service {
      id
      title
    }
    resources {
      id
      name
    }
    lineItemProperties {
      id
      name
      value
    }
  }
}
```

```curl
curl --request POST \
--header 'content-type: application/json' \
--header 'x-api-key: YOUR_TOKEN' \
--header 'x-client-id: YOUR_CLIENT_ID' \
--header 'x-shop-id: YOUR_SESAMI_ADMIN_SHOP_ID' \
--url 'https://api.sesami.co/graphql' \
--data '{"query":"query GetBooking($id: String!, $timezone: String) { getAppointment(id: $id, timezone: $timezone) { id status datetime rangeStart rangeEnd customer { firstName lastName email } service { title } resources { name } locationId } }","variables":{"id":"64f1c2a9e4b0a7d3c8e91b25","timezone":"UTC"}}'
```

### Booking fields

| Field | Description |
|-------|-------------|
| `status` | Booking status, for example `pending`. |
| `customer` | The customer who holds the booking. `email` is how most marketing tools match a profile. |
| `datetime`, `rangeStart`, `rangeEnd` | Start and end as `YYYY-MM-DD HH:mm:ss` in the `timezone` you requested. The string has no offset. |
| `customerTimezone` | The customer's time zone when they booked. |
| `service` | The booked service. |
| `variantTitle` | The option the customer chose, for example a duration. |
| `locationId` | Location id. See step 3. |
| `resources` | The team members, rooms or equipment assigned. |
| `price`, `currency` | Booking price and its currency. |
| `orderId`, `orderName` | The Shopify order, when the booking has one. |
| `customerManagementLink` | Link for the customer to manage the booking, when available. |
| `lineItemProperties` | Answers to the booking form, as `{ id, name, value }`. |

## 3. Add the location and names

The booking references its location by id. Fetch the location for its name, address and time zone. Use the location's `timezone` when you show the booking time to the customer. Locations, services and resources change rarely, so cache them.

<Tabs groupId="api" queryString>
<TabItem value="graphql" label="GraphQL" default>

The service and resource names already came back in step 2. Fetch the location:

```graphql
query GetLocation($shop: String!, $locationId: String!) {
  getLocation(shop: $shop, locationId: $locationId) {
    id
    name
    timezone
    businessAddress {
      address
      suite
      city
      state
      zipCode
      country
    }
  }
}
```

</TabItem>
<TabItem value="rest" label="REST">

| Request | Name field |
|---------|-----------|
| `GET /api/v1/{shop}/locations/{id}` | `name`, plus `timezone` and `businessAddress` |
| `GET /api/v1/{shop}/services/{id}` | `title` |
| `GET /api/v1/{shop}/resources/{id}` | `name` |

## List bookings

To backfill or reconcile, list bookings instead of fetching them one at a time.

<Tabs groupId="api" queryString>
<TabItem value="graphql" label="GraphQL" default>

Use the `getAppointments` query with your Shop ID as `shop`. It returns the same booking fields, with `service` and `resources` resolved, plus a `cursor` per item for paging.

</TabItem>
<TabItem value="rest" label="REST">

```
GET https://api.sesami.co/api/v1/{shop}/appointments?timezone=UTC
```

Returns `{ "data": [...] }` with the same booking shape. See the [REST reference](https://api.sesami.co/swagger) for filters and paging.

</TabItem>
